# TrenchBroom support

Edit Dystopia 2 maps (`maps/*.map`, Quake map format with Valve 220 UVs) in
[TrenchBroom](https://trenchbroom.github.io/).

| Path | What |
| --- | --- |
| `Dystopia2/GameConfig.cfg` | Game config (format version 9, needs TrenchBroom **2024.2 or newer**) |
| `Dystopia2/d2.fgd` | Entity definitions for every entity the game reads |
| `Dystopia2/textures/d2/*.png` | Editor previews of the procedural in-game materials (`d2/floor` -> `textures/d2/floor.png`) |
| `Dystopia2/Icon.png` | Icon shown in TrenchBroom's game list |
| `gen-textures.mjs` | Regenerates the PNGs and the icon (no dependencies) |

The game draws its materials procedurally (`packages/client/src/render/materials.ts`),
so the PNGs only exist for the editor. After adding or restyling a material there, add it
to `gen-textures.mjs` and run:

```sh
node tools/trenchbroom/gen-textures.mjs
```

## Setup

1. **Install TrenchBroom** (2024.2+; 2026.2 is current). On Arch:
   `yay -S trenchbroom-appimage` (tracks the latest release; `trenchbroom-bin` also works but lags
   behind), or `flatpak install flathub com.kristianduske.TrenchBroom`, or grab the AppImage from
   the [GitHub releases](https://github.com/TrenchBroom/TrenchBroom/releases).
2. **Install the game config** by symlinking it into TrenchBroom's user games directory,
   which on Linux is `~/.TrenchBroom/games/` (the Flatpak uses the same path). From the repo root:
   ```sh
   mkdir -p ~/.TrenchBroom/games
   ln -s "$PWD/tools/trenchbroom/Dystopia2" ~/.TrenchBroom/games/Dystopia2
   ```
   A copy works too, but has to be refreshed after every FGD/config change. If unsure where the
   directory is, the folder button under the game list in *Preferences > Games* opens it.
3. **Set the game path**: restart TrenchBroom, open *Preferences > Games > Dystopia 2* and set
   *Game Path* to the **repository root** (e.g. `~/git/dystopia2`). The config loads materials from
   `<game path>/tools/trenchbroom/Dystopia2/textures`, so any other path means missing textures.
4. **Open a map** with *File > Open* (`maps/d2_quarantine.map`). The generator writes the header
   `// Game: Dystopia2` while the config is called `Dystopia 2`, so TrenchBroom asks for the game on
   first open: pick *Dystopia 2* and the *Valve* format. Saving rewrites the header, which the game's
   map parser ignores.

`maps/d2_quarantine.map` is generated by `tools/maps/quarantine.ts` (`npx tsx tools/genmaps.ts`);
running the generator overwrites hand edits made in TrenchBroom.

## Mapping reference

**Teams**: `1` = Punks, `2` = Corps. `team` keys use dropdowns; `0` means "none", "both" or "anyone"
depending on the entity (see its help text in the entity inspector).

**Targets**: `target` is a comma-separated list of targetnames, each optionally suffixed with
`:action`, e.g. `door_bay:open,core_ff:disable,spawn_mid`. Names without a suffix get the firing
entity's default action (`action` key on `d2_node` / `d2_screen` / `trigger_crack`, otherwise the
generic `trigger`). A `d2_relay` passes the action it was fired with on to its unsuffixed targets.
Actions per entity:

| Entity | Actions |
| --- | --- |
| `func_door` | `open` `close` `toggle` `lock` `unlock` |
| `func_forcefield` | `enable` `disable` `toggle` `capture` |
| `cyber_ice` | `pass0`..`pass3` `open` (= pass3) `close` (= pass0) |
| `d2_spawngroup` | `enable` `disable` `capture` |
| `d2_turret` | `capture` `enable` `disable` `toggle` |
| `d2_camera` | `capture` |
| `d2_jackin` | `enable` `disable` `toggle` |
| `d2_node`, `d2_screen` | `enable` `disable` |

TrenchBroom draws link lines (and validates) only when a `target`-style key holds a single plain
name. Lists and `:action` suffixes show up as "missing link target" warnings in the Issue
Browser; they are fine for the game. Single-name references (`cyberspawn*`, `doorway` on nodes,
`objective`, `group`) always get link lines, so broken ones are real mistakes.

**Spawning**: `info_player_punk` / `info_player_corp` set `group` to a `d2_spawngroup` targetname.
A team spawns at its points whose group it owns and that is enabled; capturing a group (e.g. from an
objective's `target`) moves the front line.

**Objectives and stages**: `d2_objective` has a `stage`; a `d2_node`, `d2_screen` or `func_breakable`
completes it through its `objective` key. The stage advances once all non-`optional` objectives of
the current stage are done; a `final` objective ends the round. Put the consequences (open gates,
swap spawn groups, enable JIPs) in the objective's `target` list with explicit `:action`s.

**Jack-In Points**: a `d2_jackin` (meatspace terminal, `angle` = the side the user stands on) sends
the avatar to the `d2_cyber_spawn` entities named by `cyberspawn` (or `cyberspawn_punk` /
`cyberspawn_corp` per team). Give several cyber spawns the same targetname to form a set; set their
`up` when they sit on a wall or ceiling.

**Nodes and doorways**: a `d2_node` is the hackable screen, normally at the back of a small node
house. Its entrance is a `cyber_ice` brush entity with `doorway 1` (usually `pass 3`, i.e. open) and
the node's `doorway` key names that ICE's targetname. The node's `target` / `action` say what hacking
does, `team` is the defending owner, `protection` adds a password or encryption, `oneway 1` stops the
owner from hacking it back, and `up` must match the surface the house is mounted on.

**Gravity tiles**: any face textured exactly `d2/cyber_floor` is a gravity tile. Touching it makes that
face the avatar's floor, which is how players walk up server walls and onto ceilings. Use
`d2/cyber_wall` / `d2/cyber_data` for surfaces that must not re-orient gravity.

**Volumes**: `trigger_*` and the cyberspace volumes (`cyber_zerog`, `cyber_jumppad`,
`cyber_speedpad`, `cyber_drain`) are never drawn or solid in game; texture all their faces with
`d2/trigger` so they stay see-through in the editor. Conversely, `d2/trigger` / `d2/clip` on world
brushes changes collision (non-solid / player clip), because the game derives contents from
textures. Create volumes via right-click > *Create Brush Entity*. The smart-tag actions *Turn
Selection into Trigger* (makes a `trigger_*` entity and applies `d2/trigger`) and *Turn Selection
into Trigger material* can be bound to keys under *Preferences > Keyboard* (search for "Tags").

**Tool textures** (invisible in game): `d2/trigger` (volumes), `d2/clip` (player clip), `d2/nodraw`
(solid, not rendered), `d2/skip`. They, `d2/forcefield` and `d2/glass` render translucent in the
editor. `func_group` / `func_detail` (and TrenchBroom groups and layers) are merged into the world.
`d2_cyberpath` entities form the bot waypoint graph for cyberspace; their `target` lists the
reachable neighbours (one-way, so list both directions).
